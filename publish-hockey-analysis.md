# Publishing `hockey-analysis/out/` to GitHub Pages

Process for taking the analysis artifacts produced in
`/home/sqlreport/git/hockey-analysis/out/` and publishing them as the data
source for a static **GitHub Pages** site in that same repo.

The site lets the visitor **pick a game**, then narrow the view by
**period**, **player**, and **event type / facet** — all client-side, from
the exported CSV/JSON. Each analysis run writes one game into
`out/<game-id>/`; the publish step mirrors every game dir and generates the
index the front-end reads.

**Hard rule:** video files (`*.mp4`, and any other `*.mov` / `*.mkv` / `*.avi`)
are **not** exported. Everything else in `out/` is.

---

## Prerequisites

The analysis code and its output currently live in `rocm-labs`
([video-analysis.ipynb](video-analysis.ipynb), [scripts/](scripts/), `out/`).
This process assumes they have been moved into `hockey-analysis` so that
running the notebook there produces `hockey-analysis/out/`. Nothing below
depends on `rocm-labs`.

## 1. What is in `out/`, and what gets published

`out/` holds one sub-directory per game, `out/<game-id>/`. Convention for
the id: `YYYY-MM-DD-<away>-<home>` lower-cased, e.g.
`2026-09-04-hcap-lhc`. Paths in the table below are **relative to one
game dir**.

| Path | Contents | Export? |
|---|---|---|
| `meta.json` | Game id, date, competition, home/away, source video — written by the analysis run (optional; fields are back-filled from the data if absent) | ✅ |
| `events.csv` | Parsed goals/penalties (period, clock, team, type, player, infraction, state, score, scorer, assists) | ✅ |
| `roster.csv` | Both teams' rosters (team, number, name, pos, flag) — **the player list** | ✅ |
| `absences.json` | Jersey numbers on the sheet but not dressed | ✅ |
| `periods/periods.json` | Period ↔ video-time ↔ wall-clock map — **the period list** | ✅ |
| `periods/*.mp4` | Cut period videos | ❌ **video** |
| `tracks/win3104.csv` | Per-frame player tracks (`frame,t_s,track_id,xyxy,foot_x,foot_y,team`) | ✅ |
| `identity/number_votes.csv` | `track_id → jersey number` map (once §6 of the notebook is done) — enables **player-level** track/asset filtering | ✅ |
| `homography/H_*.json` | pixel→metre homography matrix, window, RMS | ✅ |
| `homography/H_*.npy` | Same matrix, NumPy binary | ⚪ optional (`.json` is the web copy) |
| `heatmaps/*.png` | Rendered positional heatmaps (all / per team) | ✅ |
| `frames/*.jpg` | Keyframe stills + calibration overlays | ✅ |
| `htrack/*.jpg` | Homography-tracking anchor / overlay stills | ✅ |
| `rink/*.{jpg,png}` | Rink-line / ice-mask detection debug | ✅ (trim candidate) |
| `p2scan/*.jpg` | Period-2 scan thumbnails (~61) | ⚪ trim candidate |
| `motion/*.jpg` | Per-frame motion debug (~750 files, ~40 MB) | ⚪ trim candidate |
| `ts/`, `ts_fine/*.jpg` | Coarse / fine timestamp-OCR crops (~190 files) | ⚪ trim candidate |

Generated by the publish step, not by the notebook:

| Path | Contents |
|---|---|
| `../games.json` | Index of every game (feeds the game `<select>`) |
| `game.json` | Per-game metadata, player list, period list, event facets, asset index (feeds the period / player / event controls) |

**Default behaviour:** copy the whole tree, drop only video. The
`trim candidate` directories are heavy debug output; drop them by
uncommenting the extra `--exclude` lines in the script if you want a lean
site. Video exclusion is not optional.

Time bookkeeping used by the filters: `periods.json` gives each period's
`vid_start` / `vid_end` in **seconds**; `tracks/*.csv` rows carry `t_s`
(seconds); asset filenames that embed a time do so in seconds
(`frames/t3122*.jpg`, `heatmaps/win3104_*.png`, `htrack/ov_2625.jpg`,
`htrack/anchor_3122.jpg`). Anything with no time in its name is treated as
period-agnostic and always shown.

## 2. Extraction scripts

### `hockey-analysis/scripts/publish_out.sh`

```bash
#!/usr/bin/env bash
# Mirror out/ (all games) into site/data/ for GitHub Pages: drop all video,
# then generate games.json + each game's game.json.
set -euo pipefail

REPO_ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
SRC="${1:-$REPO_ROOT/out}"
DEST="${2:-$REPO_ROOT/site/data}"

[ -d "$SRC" ] || { echo "no such dir: $SRC" >&2; exit 1; }
mkdir -p "$DEST"

# 1. Mirror, excluding video (and anything else non-web you add here).
rsync -a --delete --prune-empty-dirs \
  --exclude='*.mp4' --exclude='*.mov' --exclude='*.mkv' --exclude='*.avi' \
  --exclude='.DS_Store' \
  "$SRC"/ "$DEST"/
  # Lean site: also drop debug-heavy dirs —
  #   --exclude='motion/***' --exclude='p2scan/***' \
  #   --exclude='ts/***' --exclude='ts_fine/***' --exclude='*.npy'

# 2. Build the game index + per-game manifests the front-end reads
#    (Pages has no autoindex, so the file lists must be baked in).
python3 "$REPO_ROOT/scripts/gen_manifest.py" "$DEST" "$SRC"

# 3. Stop Jekyll from touching the tree.
touch "$DEST/../.nojekyll"

# 4. Fail loudly if any video slipped through.
if find "$DEST" -type f \( -name '*.mp4' -o -name '*.mov' -o -name '*.mkv' -o -name '*.avi' \) | grep -q .; then
  echo "ERROR: video leaked into $DEST" >&2; exit 1
fi

echo "published $(find "$DEST" -type f | wc -l) files -> $DEST"
```

### `hockey-analysis/scripts/gen_manifest.py`

```python
#!/usr/bin/env python3
"""Build the site's data index from a mirrored out/ tree:

  site/data/games.json           - one row per game            (game selector)
  site/data/<game-id>/game.json  - metadata + players + periods + event
                                   facets + grouped asset index

A "game" is any immediate sub-dir of out/ that has an events.csv. If out/
holds a single game's files directly, it is treated as one game, id "game".
"""
import ast
import csv
import json
import subprocess
import sys
import time
from pathlib import Path

dest = Path(sys.argv[1]).resolve()
src = Path(sys.argv[2]).resolve() if len(sys.argv) > 2 else None


def git(*args, cwd):
    try:
        return subprocess.check_output(["git", *args], cwd=cwd, text=True).strip()
    except Exception:
        return None


def read_csv(path):
    with open(path, newline="") as fh:
        return list(csv.DictReader(fh))


def parse_list(cell):
    try:
        v = ast.literal_eval(cell) if cell else []
        return [str(x) for x in v] if isinstance(v, (list, tuple)) else []
    except Exception:
        return []


def game_dirs(root):
    if (root / "events.csv").is_file():
        return [(root, "game")]
    return [(d, d.name) for d in sorted(root.iterdir())
            if d.is_dir() and (d / "events.csv").is_file()]


def asset_index(gdir):
    groups: dict[str, list] = {}
    for p in sorted(gdir.rglob("*")):
        if not p.is_file() or p.name in {"game.json", "meta.json"}:
            continue
        rel = p.relative_to(gdir)
        top = rel.parts[0] if len(rel.parts) > 1 else "."
        groups.setdefault(top, []).append(
            {"path": str(rel).replace("\\", "/"), "bytes": p.stat().st_size,
             "ext": p.suffix.lower().lstrip(".")})
    return groups


def build_game(gdir, gid):
    events = read_csv(gdir / "events.csv") if (gdir / "events.csv").is_file() else []
    roster = read_csv(gdir / "roster.csv") if (gdir / "roster.csv").is_file() else []
    meta = json.loads((gdir / "meta.json").read_text()) if (gdir / "meta.json").is_file() else {}

    pj = gdir / "periods" / "periods.json"
    periods = json.loads(pj.read_text()).get("periods", []) if pj.is_file() else []

    teams = ([r["team"] for r in dict.fromkeys(r["team"] for r in roster)]
             if roster else list(dict.fromkeys(e["team"] for e in events if e.get("team"))))
    home = meta.get("home") or (teams[0] if teams else None)
    away = meta.get("away") or (teams[1] if len(teams) > 1 else None)

    goals = [e for e in events if e.get("type") == "goal" and e.get("score")]
    score = meta.get("score") or (goals[-1]["score"] if goals else None)  # home:away

    # players that appear anywhere in events -> "hasEvents" hint for the picker
    involved = set()
    for e in events:
        involved.update(x for x in (e.get("player"), e.get("scorer")) if x)
        involved.update(parse_list(e.get("assists", "")))

    players = [
        {"team": r["team"], "number": r.get("number"), "name": r["name"],
         "pos": r.get("pos") or None, "flag": r.get("flag") or None,
         "hasEvents": r["name"] in involved}
        for r in roster
    ]

    game = {
        "id": gid,
        "date": meta.get("date"),
        "competition": meta.get("competition"),
        "video": meta.get("video"),
        "home": home, "away": away, "score": score,
        "label": " · ".join(x for x in [
            meta.get("date"),
            f"{away} @ {home}" if home and away else gid,
            f"({score})" if score else ""] if x),
        "periods": [
            {"period": p.get("period"), "vid_start": p.get("vid_start"),
             "vid_end": p.get("vid_end"), "dur_min": p.get("dur_min"),
             "wall_start": p.get("wall_start"), "wall_end": p.get("wall_end")}
            for p in periods
        ],
        "players": players,
        "filters": {
            "eventTypes":  sorted({e["type"] for e in events if e.get("type")}),
            "eventStates": sorted({s for e in events
                                   for s in (e.get("state") or "").split(",") if s}),
            "infractions": sorted({e["infraction"] for e in events if e.get("infraction")}),
            "teams": [t for t in (home, away) if t],
        },
        "hasTrackIdentity": (gdir / "identity" / "number_votes.csv").is_file(),
        "assets": asset_index(gdir),
    }
    (gdir / "game.json").write_text(json.dumps(game, indent=2))
    return game


games = []
for gdir, gid in game_dirs(dest):
    g = build_game(gdir, gid)
    games.append({k: g[k] for k in ("id", "label", "date", "competition",
                                    "home", "away", "score")}
                 | {"dir": gid, "periods": len(g["periods"]),
                    "players": len(g["players"])})

index = {
    "generatedAt": time.strftime("%Y-%m-%dT%H:%M:%SZ", time.gmtime()),
    "sourceCommit": git("rev-parse", "HEAD", cwd=src) if src else None,
    "gameCount": len(games),
    "games": games,
}
(dest / "games.json").write_text(json.dumps(index, indent=2))
print(f"indexed {len(games)} game(s):", ", ".join(g["id"] for g in games) or "none")
```

  "generatedAt": "2026-09-05T15:00:00Z",
  "sourceCommit": "7afa58e…",
  "gameCount": 1,
  "games": [
    {
      "id": "2026-09-04-hcap-lhc", "dir": "2026-09-04-hcap-lhc",
      "label": "2026-09-04 · HCAP @ LHC · (4:1)",
      "date": "2026-09-04", "competition": "U18-Elit",
      "home": "LHC", "away": "HCAP", "score": "4:1",
      "periods": 3, "players": 40
    }
  ]
}

## 3. Site source layout

```
hockey-analysis/site/
  .nojekyll
  index.html          # game / period / player / event controls + views
  app.js
  style.css
  data/               # produced by publish_out.sh
    games.json
    2026-09-04-hcap-lhc/
      game.json
      events.csv  roster.csv  absences.json
      periods/  tracks/  homography/  heatmaps/  frames/  htrack/  rink/  …
    2026-09-18-lhc-genf/
      game.json  events.csv  …
```

`index.html` / `app.js` are hand-written once. On load they fetch
`data/games.json` and fill the game `<select>`; on game change they fetch
`<game-id>/game.json` and rebuild the period / player / event controls from
it, then fetch that game's `events.csv` (and `tracks/*.csv` if a view needs
it). Nothing is hard-coded — `games.json` and `game.json` are the source of
truth for what exists. See [§7](#7-interactive-selection--filtering) for the
control wiring and filter predicates.

### Where does `site/data/` come from — commit it, or build it in CI?

| Model | `site/data/` | `out/` in git | Repo growth | Notes |
|---|---|---|---|---|
| **A – commit data** | committed | committed or not | +50–88 MB | Simplest. Pages serves files directly. |
| **B – build in CI** | git-ignored | committed (or restored from Release / artifact / LFS) | minimal | Actions runs `publish_out.sh` before deploy. Required if `out/` is LFS-backed (Pages does not serve LFS blobs; the Actions checkout smudges them to real bytes). |

Add to `.gitignore` for Model B:

```
site/data/
site/.nojekyll
```

## 4. GitHub Actions → Pages

`.github/workflows/pages.yml`:

```yaml
name: Publish analysis site
on:
  push:
    branches: [main]
    paths:
      - "out/**"
      - "site/**"
      - "scripts/publish_out.sh"
      - "scripts/gen_manifest.py"
      - ".github/workflows/pages.yml"
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          lfs: true              # only needed under Model B with LFS-backed out/
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - name: Stage out/ into site/data (exclude video) + manifest
        run: bash scripts/publish_out.sh
      - uses: actions/upload-pages-artifact@v3
        with:
          path: site

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deploy.outputs.page_url }}
    steps:
      - id: deploy
        uses: actions/deploy-pages@v4
```

Under Model A the "Stage" step is still safe to keep (it is idempotent and
re-verifies the no-video rule); drop it and the Python setup only if you
want CI to publish exactly what was committed.

**One-time:** repo **Settings → Pages → Build and deployment → Source:
GitHub Actions**.

Important: the `github-pages` environment is protected by the repository's branch
policy. In practice, the deploy job must run from `main` unless you explicitly
allow a different branch in the environment protection rules. If you try to
publish from a feature branch like `add-site`, the deploy job will be rejected.

Also note: if `out/` has not been generated yet, the publish script now creates an
empty `site/data/games.json` instead of failing, so the site still deploys cleanly
while data is absent.

## 6. Re-publishing after a new analysis run

1. Run [video-analysis.ipynb](video-analysis.ipynb) for the game →
   `out/<game-id>/` is written (a new game) or refreshed (a re-run). Adding
   a game only adds one sub-tree; existing games are untouched.
2. `bash scripts/publish_out.sh` locally — the script aborts if any video
   reached `site/data/`; check the `indexed N game(s)` line and per-game
   file counts look sane.
3. Commit the changed paths (`out/<game-id>/` and/or `site/data/`) and push
   to `main`.
4. The `pages.yml` workflow rebuilds `site/data/`, regenerates
   `games.json` + every `game.json`, and redeploys.

`rsync --delete` means stale files — including whole games removed from
`out/` — are dropped from `site/data/`, so the published set always matches
the current `out/`.

Optional pre-commit guard (`.git/hooks/pre-commit`):

```bash
#!/usr/bin/env bash
if git diff --cached --name-only | grep -Eq '^site/data/.*\.(mp4|mov|mkv|avi)$'; then
  echo "refusing commit: video file staged under site/data/"; exit 1
fi
```

## 7. Interactive selection & filtering

All four controls filter **client-side** over data already fetched for the
selected game — no rebuild, no server. State lives in the URL query string
(`?game=…&period=…&player=…&type=…`) so a filtered view is shareable and
survives reload; write it with `history.replaceState` on every change and
read it on load.

### 7.1 Game

`<select>` populated from `games.json → games[]`, option text = `game.label`,
value = `game.dir`. On change: `fetch(\`data/${dir}/game.json\`)`, then
`fetch(\`data/${dir}/events.csv\`)`, reset the other three controls from the
new `game.json`, clear any cached `tracks` CSV.

### 7.2 Period

Options: **All**, then one per `game.periods[]` —
label e.g. `P1 · 31.4 min · 16:58–17:30`, value = `period` number.
Selecting period *P* keeps:

- **events** — `row.period === String(P)`.
- **tracks** — rows with `vidStart ≤ row.t_s < vidEnd`, where
  `vidStart/vidEnd` come from that period entry.
- **time-stamped assets** — parse the integer in the filename
  (`t3122` → 3122, `win3104` → 3104, `ov_2625` → 2625, `anchor_3122` → 3122)
  as seconds and keep those that fall in `[vidStart, vidEnd)`. Assets with
  no number in the name are period-agnostic → always shown.

```js
const periodOfSeconds = (sec, periods) =>
  periods.find(p => sec >= p.vid_start && sec < p.vid_end)?.period ?? null;
const assetSeconds = name => { const m = name.match(/(\d{2,6})/); return m ? +m[1] : null; };
```

### 7.3 Player

`<optgroup>` per team from `game.players[]`, option text
`#{number} {name} {pos}`, dimmed / suffixed “no events” when
`!player.hasEvents`, value = `player.name` (names are unique in the sheet).
Selecting a player keeps:

- **events** — `row.player === name || row.scorer === name ||
  parseAssists(row.assists).includes(name)`
  (assists cell is a Python-list string: `"['Wand Nolan', …]"` — parse with
  a small regex / JSON5, not `eval`).
- **tracks & time-stamped assets** — only when
  `game.hasTrackIdentity === true`: join `tracks.track_id →
  identity/number_votes.csv → jersey number → roster name`. When it is
  `false` (current state — notebook §6 not yet run) the player control still
  filters **events**, and the tracks/heatmap views show a “player-level
  tracking not available for this game” note instead of filtering.

### 7.4 Event filter

Built from `game.filters`. Primary control = a checkbox per
`filters.eventTypes` (`goal`, `penalty`), all checked by default. Optional
facet chips, each a multi-select that is inactive until something is picked:

| Facet | Source | Applies to |
|---|---|---|
| Team | `filters.teams` | `row.team` |
| State | `filters.eventStates` (`EQ`, `PP1`, `GWG`, `EN`, `SH`, …) | any token in `row.state.split(',')` |
| Infraction | `filters.infractions` | `row.infraction` (penalty rows only) |

An event row is shown iff it passes **every active** predicate:

```js
function eventVisible(row, sel, periods) {
  if (sel.period !== "all" && row.period !== String(sel.period)) return false;
  if (sel.player && !(row.player === sel.player
        || row.scorer === sel.player
        || parseAssists(row.assists).includes(sel.player))) return false;
  if (!sel.types.has(row.type)) return false;
  if (sel.teams.size  && !sel.teams.has(row.team)) return false;
  if (sel.states.size && !(row.state || "").split(",").some(s => sel.states.has(s))) return false;
  if (sel.infractions.size && !sel.infractions.has(row.infraction)) return false;
  return true;
}
```

The heatmap / frame galleries reuse the same `sel` — filter their asset
lists by `periodOfSeconds(...)` and (when identity exists) by player — so
picking a period or player narrows tables and figures together.

## 8. Notes

- **Why video is excluded.** The period cuts (`out/periods/*.mp4`) and the
  planned `segments/` and `highlights/` clip directories run to hundreds of
  MB up to GB — past GitHub's per-file warnings and the practical Pages size
  budget, and unnecessary for a data-and-figures site. The exported stills
  already carry the visual content. If short clips are ever wanted, host
  them outside the repo (GitHub Releases, object storage) and link out.
- **`.nojekyll` is required.** Without it, Jekyll tries to process ~1000
  files at build time and can silently drop or rewrite some. With it, Pages
  serves the `data/` tree byte-for-byte.
- **No directory autoindex.** GitHub Pages will not return a listing for
  `data/<game-id>/frames/` etc. The front-end learns what exists only from
  `games.json` and each `game.json` (`assets` block) — that is what
  `gen_manifest.py` bakes in.
- **Player-level track/asset filtering needs the identity map.** Until the
  notebook's §6 (jersey OCR → `identity/number_votes.csv`) runs, tracks are
  keyed by anonymous `track_id`/team only. `game.json.hasTrackIdentity`
  reflects this; the player control filters **events** regardless, and the
  track/heatmap views degrade gracefully.
- **Game id / `meta.json`.** The analysis run owns the `out/<game-id>/`
  name and should drop a `meta.json` (date, competition, home/away, video).
  If it doesn't, `gen_manifest.py` back-fills: teams from `roster.csv`,
  score from the last `goal` row of `events.csv` (`home:away`), and the id
  from the directory name.
- **`.npy` files.** `homography/*.npy` is copied by default but is not
  browser-consumable; the paired `*.json` holds the same matrix. Add
  `--exclude='*.npy'` to drop them.
- **Repo / site size.** Full image export is ~88 MB; ~40–50 MB if you trim
  `motion/ p2scan/ ts/ ts_fine/`. Both are under the ~1 GB Pages soft limit,
  but watch the trend across re-runs.
- **Git LFS.** If `out/` is committed and grows, track the large binary
  directories with LFS — but Pages does **not** serve LFS-backed files
  directly, so you must then use Model B (CI regenerates `site/data/` from
  the smudged checkout).
